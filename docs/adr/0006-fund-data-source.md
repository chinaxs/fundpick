# 0006 · 第一期基金数据源选用 AkShare（明确标注为临时方案）

- **状态**：已采纳（**临时**，商业化前必须替换）
- **日期**：2026-11-06

## 背景

产品定位是商业化基金分析网站，需要覆盖全市场公募基金的基础信息、净值、区间收益、风险指标。
但数据预算尚未确定，如果先采购持牌数据（Wind / Choice / 聚源），一年成本数万元起，且在产品形态未验证前投入风险高。

## 决策

第一期使用 **AkShare** 作为数据源，同时在 `app/datasources/` 建立 `FundDataProvider` 协议，
业务代码只依赖协议，不直接调用 `akshare`。换源时新增一个实现类即可，采集脚本与接口无需改动。

## 理由

1. **零成本验证**：AkShare 覆盖基金列表、排行、净值、风险指标四类数据，足够支撑"筛选排行"这个第一期核心功能。
2. **采集成本低**：排行接口一次返回某类型全部基金的近 1 周/1 月/1 年/3 年/成立以来收益，不必自己拉全量净值再算。
3. **风险可控**：接口抽象层隔离了数据源差异，替换成本被限制在 `akshare_source.py` 一个文件。

## 明确的风险（不要忽略）

| 风险 | 说明 |
| --- | --- |
| **商业使用授权** | Tushare 服务协议原文写明"个人的、不可转让的、**非商业用途**的许可"；AkShare 是 MIT，但它抓取的是东方财富、天天基金等站点的公开页面，商用需遵守这些数据方的服务条款。**公开数据不等于可商用数据。** |
| **稳定性** | 依赖第三方网页结构，上游改版即失效；无 SLA；高频请求可能触发反爬。 |
| **数据完整性** | 缺基金规模、成立日期、托管费率等字段；部分指标（如盘中估值）口径不统一。 |
| **合规** | 若产品提供"买什么"的建议，可能触及基金投资顾问业务的监管要求，需要牌照或与持牌机构合作。仅提供数据工具与历史业绩展示，风险相对较低，但边界需法务确认。 |

## 备选方案

| 方案 | 为什么不选（现阶段） |
| --- | --- |
| Wind / Choice | 数据最全最稳，但年费高、需商务流程，不适合产品形态未定的阶段 |
| 聚源 / 通联 | 同上，且偏向机构 API 对接，接入周期长 |
| 交易所 / 基金业协会公开数据 | 权威但只覆盖部分字段（如净值），拿不到完整排行与指标 |
| 自建爬虫 | 与 AkShare 同样的合规与稳定性问题，还多一份维护成本 |

## 后果

- 好处：零成本把产品跑通，验证"筛选排行"是否是用户真正需要的。
- 代价：数据不完整（规模/成立日期为空）、风险指标需逐只补采（1 万只约 2 小时）、商用有法律风险。
- **替换触发条件**（任一满足就必须换源）：
  1. 开始对外收费；
  2. 需要展示规模、持仓、盘中估值等 AkShare 缺失的字段；
  3. 出现因数据错误导致的用户投诉。
- 替换方式：实现 `FundDataProvider` 的新类 → 在 `app/datasources/__init__.py` 切换 → 重跑采集。
