# ADR-0007：门户浏览器请求走同源反向代理，不依赖 CORS 白名单

- 状态：已采纳
- 日期：2026-11-06
- 相关：[ADR-0002](0002-nuxt-for-portal.md)

## 背景

门户初期让浏览器直连 `http://127.0.0.1:8000/api/v1`，后端用 `CORS_ORIGINS`
显式枚举允许的源。上线前测试发现：用 `http://localhost:3000` 打开正常，
换成 `http://127.0.0.1:3000` 就整页报 CORS 错误，且不同接口表现不一致
（SSR 已渲染的内容正常，客户端重新发起的请求失败）。

## 问题本质

浏览器的「源」= `协议 + 主机 + 端口`，三者任一不同即为跨域。
于是下面这些在本机其实**是五个不同的源**：

```
http://localhost:3000
http://127.0.0.1:3000
http://[::1]:3000
http://localhost:5174
http://127.0.0.1:5174
```

白名单是穷举式的，只要漏一个组合就报错；开发时改端口、换 hostname、
用局域网 IP 预览，都会重新触发。这类问题难以在测试阶段发现，因为：

- `curl` 不发 `Origin` 头，永远看不到 CORS 失败；
- SSR 阶段请求由 Node 发出，不受同源策略约束，页面"看起来是好的"；
- 只有浏览器在 hydration 后重新发起请求时才暴露。

## 决策

**浏览器侧一律请求同源相对路径 `/api/v1`，由 Nitro 反向代理转发到后端。**

```ts
// nuxt.config.ts
runtimeConfig: {
  apiBase: 'http://127.0.0.1:8000/api/v1', // 服务端私有：SSR 直连
  public: { apiBase: '/api/v1' },          // 浏览器：同源
},
routeRules: {
  '/api/v1/**': { proxy: 'http://127.0.0.1:8000/api/v1/**' },
},
```

```ts
// useApiBase()
return import.meta.server ? config.apiBase : config.public.apiBase
```

后端 CORS 保留，但改为「开发环境用正则放行本机任意端口，生产必须显式配置」，
仅作为直接调用 API（Swagger、第三方客户端）的兜底，不再承担页面主链路的跨域。

## 理由

| 维度 | 同源代理 | 扩大 CORS 白名单 |
| --- | --- | --- |
| 正确性 | 浏览器不跨域，不存在漏配 | 必须枚举每个源组合 |
| 环境迁移 | 换域名/端口/IP 无需改配置 | 每换一次改一次，且容易忘 |
| 安全 | 浏览器不接触后端地址，后端可不暴露公网 | 白名单一旦放宽（如 `*`）风险更大 |
| 部署形态 | 与「同域部署 / 网关统一入口」一致 | 要求前后端长期跨域，反而不常规 |

## 代价

- 多一跳转发（实测本机 < 5ms，可忽略）。
- SSR 与浏览器使用不同基址，`useApiBase()` 必须区分 `import.meta.server`，
  新人容易在别处直接读 `public.apiBase` 而漏掉服务端分支。
- Nitro 需要能访问后端地址，容器部署时 `NUXT_API_BASE` 要填服务名而非 127.0.0.1。

## 需要遵守

1. 页面/组件**不得**直接调用 `$fetch` 绝对地址，统一走 `useApiBase()`。
2. `.env` 里 `NUXT_PUBLIC_API_BASE` 保持 `/api/v1`，改回绝对地址会重新引入 CORS。
3. 新增后端前缀时同步补 `routeRules`（当前只代理 `/api/v1/**`）。
4. 生产若用 Nginx 反代，可去掉 Nitro 代理，但前端基址仍保持相对路径。
