# ADR-0016：持仓以统一账本重放为准

- 状态：已采纳
- 日期：2026-11-08

## 背景

早期实现把"剩余份额/剩余成本"写在每笔交易行上，作为确认当时的快照。
这在只有买卖时是对的，但补录拆分、红利再投、转换后，历史快照就过期了：

- 持仓页读快照 → 显示 500 份；
- 核对页另算一套 → 显示 1000 份；
- 卖出校验再读快照 → 按 500 份拒绝。

三处各算一套，是"核对页对了、主流程还错"的根因。

## 决策

新增 `services/ledger.py`，把同一基金的**全部**有效事件（买卖流水 +
公司行为）按日期重放，得到唯一的持仓状态：

- 同一日期内先处理买卖，再处理公司行为（拆分/再投通常按日终生效）；
- 成本按**平台**分别用移动平均结转，与确认时的 `calculate()` 完全一致
  （平台 A 卖出不影响平台 B 的成本）；
- 批次（lot）保留"持有期起点"，供赎回费档位使用；拆分按比例缩放批次；
- 公司行为带 `platform`，只落到一个平台；缺平台的旧数据按当日份额最大的平台归属。
  单平台查询是"全平台重放后投影"，不是"只喂该平台事件"——后者会让一笔再投
  在 A、B 两个平台各加一次（见 [ADR-0017](0017-company-action-platform-and-idempotency.md)）。

使用方：持仓总览、可卖份额校验、FIFO 费率、收益核对、持仓标识、AI 快照。
流水行上的 `remaining_shares/remaining_cost` 退化为"确认当时的历史快照"，
只用于展示单笔记录，不再参与任何计算。

## 备选方案

| 方案 | 为什么没选 |
| --- | --- |
| 补录公司行为时批量重算所有后续流水行 | 一次补录要改 N 行，失败回滚成本高；且并发补录会互相覆盖 |
| 只改核对页，卖出仍读快照 | 正是验收发现的问题：页面说 1000 份，卖出只认 500 份 |
| 直接改成 FIFO 成本 | 与既有确认口径（移动平均）冲突，历史收益全部变化 |

## 后果

- 任何"份额/成本"都只有一套算法，补录历史事件后立即生效；
- 每次读取要重放该基金的事件（通常几十条），可接受；单基金事件特别多时
  可按需加缓存，但缓存必须随事件写入失效；
- 转换改为一次写两条配对流水（`transfer_group`），转出成本按移动平均结转（与卖出同口径），
  删除时任一条会整组删除，避免留下单边份额。
