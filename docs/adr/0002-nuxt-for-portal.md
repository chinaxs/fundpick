# 0002 · 门户用 Nuxt（SSR），后台用 Vue SPA

- **状态**：已采纳
- **日期**：2026-11-05

## 背景

两个前端面向完全不同的场景：

- **门户**：企业官网 / 资讯站，内容要被搜索引擎收录，首屏要快，访客多数从搜索或分享链接进入。
- **后台**：登录后才能用的管理系统，无 SEO 需求，交互复杂，长期停留。

## 决策

门户使用 **Nuxt 4（SSR）**，后台使用 **Vue 3 + Vite（SPA）**。两者不共享运行时，只共享 `packages/shared` 的类型与纯函数。

## 理由

1. SEO 是门户的硬指标：SPA 的空壳 HTML 对爬虫不友好，SSR 能直接输出内容（已验证：详情页 HTML 里含完整标题与正文）。
2. 首屏体验：SSR 直出 + 客户端水合，比"白屏 → 请求 → 渲染"快一个量级。
3. 后台不需要 SSR，引入 Nuxt 只会增加构建复杂度与部署负担（需要 Node 运行时），SPA 静态托管即可。
4. 两者技术栈同源（Vue），人员可在两个项目间流动，成本低于"一个 React 一个 Vue"。

## 备选方案

| 方案 | 为什么不选 |
| --- | --- |
| 两个都用 Nuxt | 后台无 SEO 需求，白付 SSR 的部署与调试成本 |
| 两个都用 Vue SPA + 预渲染 | 预渲染只适合静态页，资讯类内容更新后需重新构建 |
| 门户用 Next.js（React） | 团队栈是 Vue，混栈会增加维护成本 |

## 后果

- 好处：门户 SEO 与首屏达标；后台部署轻量。
- 代价：多一套 Nuxt 心智模型（`app/` 目录约定、`useAsyncData`）；门户部署需要 Node 进程或静态生成。
- 重新评估触发条件：如果门户内容全部静态且更新极少，可改为 `nuxt generate` 纯静态部署。
