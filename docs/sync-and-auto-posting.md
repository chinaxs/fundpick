# 数据同步、新鲜度与自动入账

本修复已合并到开源`main`：数据新鲜度监控、推荐同步计划和后台自动入账作为公开基础功能维护。

## 本次查到的断点

后台的“立即同步”原本能执行，但只运行所选模式一次，不会自动配置周期任务。当前库原先没有任何`sync_schedules`记录；最近一次基础同步在2026-11-09 15:00完成，那时当日官方净值尚未披露。

“滞后3天”按自然日计算，将周五11月6日到周一11月9日视为3天延迟。该口径对周末、节假日和当晚披露过程不合适。

待入账的025196申请净值日为11月6日，公开确认规则T+1，预计确认日11月9日；对应净值已存在。实际卡点是费率页使用“申购费率”标题，旧解析只识别“申购费率（前端）”；唯一一行“--- / 0.00%”也未被识别为明确免申购费。此时系统保持未知而非猜零，但此前没有独立后台重试循环，主要依赖页面请求或一次同步后的补齐。

## 更新后的运行方式

后台已补齐9条推荐计划，均按北京时间、已核对的证券交易日历执行：

| 时间 | 内容 |
| --- | --- |
| 08:30 | 基础目录与最新快照 |
| 09:00、18:30、21:00、23:00 | 最新净值与区间收益快照 |
| 09:15、18:45、21:15、23:15 | 持仓、关注、待入账基金的历史净值和可测算风险 |

补齐计划幂等，不覆盖已有计划、时刻或停用选择。证券休市日和未知日历年度不自动推算基金同步；资讯模式独立。任务互斥沿用数据库锁，冲突6小时内补跑；API服务必须持续在线。新安装可在采集监控点击“补齐推荐计划”，并检查调度器已开启。

新`tracked`模式汇总有效会员的关注、持仓与待入账基金，不向全市场逐只高频采集历史数据；针对这些实际使用的基金更新完整净值序列和缺失风险。快照源出错或为空会计入失败，优先更新任务发现上游未达披露基准也会记录待补采，避免将异常写成全部成功。

## 新鲜度判断与显示

普通境内基金按北京时间交易日历判断；以22:00作为运营核对时间，之前先检查上一交易日，22:00及以后检查当日。22:00不是所有基金的保证发布时间，晚披露产品仍需以真实数据为准。

因此，11月9日白天保留11月6日净值不等于缺失3个交易日；11月9日22:00后如果仍只有11月6日，则缺失1个交易日。

后台同时显示最新披露日、应披露基准、缺失交易日、达标/待更新/无净值基金数、特殊品种数量、调度器和计划状态、最近同步与自动入账核对时间。即使最新一只基金已更新，其他基金存在缺项也会提示“部分基金仍需补采”。QDII、FOF、货币基金及暂停品种不直接套用普通基金的每日单位净值规则。无数据不会自动视为已达标。

这些机制保证持续检查、重试和暴露异常，不能保证第三方数据源永远及时或可用。全市场仍有缺失和延迟字段，后台保留真实清单供定向补采，不把“任务已执行”宣传成“全部数据最新”。

## 自动入账

新增独立后台循环，默认每60秒扫描到期自动申请，不要求用户保持页面打开，也不依赖市场同步开关。条件必须同时满足：申请有效、确认日已到、精确净值日已有数据、公开费用能明确计算、份额及完整历史有效。

数据库条件更新抢占每笔重试，多worker不重复处理；失败或未知信息5分钟后重试，过期抢占可恢复。按待重试时间与申请日期推进，避免前几条未知申请永远阻塞后面的记录。停用会员、撤销/删除记录与手工核对申请不被后台自动入账；最终交易仍受会员锁、幂等键和撤销并发校验保护。

`last_attempt_at`、`next_retry_at`持久化并在待入账页面显示。入账或撤销后清除重试状态，入账时清理旧等待提示。费率缓存新增解析版本，旧版漏规则缓存会重新解析；缺失规则缓存5分钟，完整规则缓存24小时。只在来源明确为唯一零费率行时解析免申购费，不按C类字母猜零，也不将每日管理/托管/销售服务费重复从单笔交易扣除。

当前025196申请已由后台自动生成交易：净值日2026-11-06、净值0.8803、公开申购费0.00，公开T+1规则对应11月9日确认；结果保留`estimated`来源，不冒充平台回执。
